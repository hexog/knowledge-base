# Повседневная работа со сценариями

## Выбрать и применить сценарий

- Для брифа перед встречей используйте [подготовку к встрече](prepare-meeting.md).
- Для оценки предложения или выбора используйте [разбор решения](assess-decision.md).
- Скопируйте нужный шаблон в диалог с подключённым MCP-клиентом и заполните только известные вводные.
- Проверьте фактические тезисы по `get_record` и `get_source_text`. Для вопросов о причинах читайте строки вокруг цитаты. В ответе оставляйте ссылки на запись, источник и диапазон строк.
- Если не нашли ошибку или пропуск, сохранять feedback не нужно. Не включайте в заметку полный транскрипт или закрытые данные, если они не нужны для описания проблемы.

## Сохранить отзыв

Сначала запишите короткую заметку в выбранный вами локальный файл. Например, `feedback-note.txt`. Затем добавьте её в локальную базу:

```sh
kb --db /path/to/knowledge-base feedback add \
  --workflow prepare_meeting \
  --rating partly_useful \
  --category incomplete_answer \
  --note-file /path/to/feedback-note.txt
```

Допустимые workflow: `prepare_meeting`, `assess_decision`, `question`, `other`. Rating: `useful`, `partly_useful`, `not_useful`. Категории: `positive`, `wrong_fact`, `incomplete_answer`, `wrong_citation`, `stale_knowledge`, `retrieval_miss`, `access_issue`, `technical`, `other`.

Чтобы просмотреть новые отзывы, выполните `kb --db /path/to/knowledge-base feedback list --status new`. Для чтения одного отзыва используйте `feedback show <id>`. После разбора можно записать решение, например:

```sh
kb --db /path/to/knowledge-base feedback set-status <id> \
  --status triaged \
  --reason "Проверить контекст цитаты в соседних строках"
```

## Форма фиксации реального кейса

Заполняйте её после реальной задачи; не подменяйте фактические примеры демонстрационными.

- Сценарий и дата:
- Что пытались сделать:
- Оценка и категория:
- Что оказалось полезным или неверным:
- Что ожидалось:
- ID записи/источника или request ID, если доступны:
- Что проверили или решили сделать дальше:

На момент добавления этой инструкции реальные кейсы ещё не собраны. Добавляйте сюда только случаи, которые действительно прошли через рабочий процесс, после удаления ненужных закрытых сведений.
