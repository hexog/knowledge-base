# Синхронизация базы знаний между устройствами

В переносимой папке базы хранятся канонические данные: оригиналы, извлечённые тексты, метаданные и записи знаний. SQLite-индекс поиска и `.operation.lock` хранятся в локальном каталоге приложения каждого устройства. Поэтому общая папка содержит только данные, из которых можно восстановить индекс.

Путь к локальному индексу строится как `LocalApplicationData/KnowledgeBase/index/<ключ-базы>/search.sqlite`. Ключ — SHA-256 нормализованного абсолютного пути к базе. Индексы и блокировки разных устройств, а также баз по разным путям не разделяются. Поле `local_index_path` в JSON-ответе `kb status` показывает путь текущего устройства.

## Переключение устройств

1. Записывайте в базу только с одного устройства за раз.
2. Перед переключением закройте приложение и дождитесь завершения синхронизации.
3. На новом устройстве выполните `kb status --verify`, затем `kb rebuild-index`. Проверка сверяет локальный индекс с каноническими файлами, включая SHA-256 оригиналов и извлечённых текстов; пересборка создаёт индекс в локальном каталоге приложения.
4. Храните независимые резервные копии базы.
5. Если синхронизация создала конфликтующие версии, не удаляйте их до ручной сверки и восстановления нужных данных.

Не переносите индекс, `.operation.lock`, секреты шлюза или реестр клиентов вместе с папкой базы. Блокировка защищает операции только между CLI и сервером на одном устройстве. Она не координирует одновременную запись с разных устройств.
